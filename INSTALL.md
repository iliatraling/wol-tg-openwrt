# Установка WOL Telegram Gateway на OpenWrt

Инструкция подготовлена и проверена на Netis NX32U с OpenWrt 25.12.6.

## 1. Требования и зависимости

Нужны:

- OpenWrt с доступом к интернету и локальной сети;
- `curl` с поддержкой HTTPS;
- пакет корневых TLS-сертификатов `ca-bundle`;
- `etherwake`;
- библиотека JSON `jshn.sh` из `libubox`;
- штатные компоненты OpenWrt `procd`, `ash` и `ping`.

Подключитесь к роутеру по SSH и проверьте систему:

```sh
echo "===== OPENWRT ====="
ubus call system board

echo "===== NETWORK INTERFACES ====="
ip link show
ip addr show

echo "===== REQUIRED COMMANDS ====="
command -v curl
command -v etherwake
command -v ping

echo "===== JSHN ====="
ls -l /usr/share/libubox/jshn.sh
```

В OpenWrt 25.12 используется пакетный менеджер `apk`:

```sh
apk update
apk add curl ca-bundle etherwake libubox
```

В более ранних версиях OpenWrt может использоваться `opkg`; названия и доступность пакетов зависят от версии и сборки.

## 2. Определяем LAN-интерфейс

Magic Packet нужно отправлять через интерфейс локальной сети. Выполните:

```sh
echo "===== LAN CONFIG ====="
uci show network.lan

echo "===== LAN STATUS ====="
ubus call network.interface.lan status

echo "===== NETWORK DEVICES ====="
ip link show

echo "===== IP ADDRESSES ====="
ip addr show
```

Найдите LAN-устройство в выводе `ubus` (поле `l3_device` или `device`) и сопоставьте его с интерфейсом, на котором назначен LAN-IP роутера.

На проверенном Netis NX32U это `br-lan`. Если у вас другое имя, используйте фактическое значение в `NETWORK_INTERFACE`.

## 3. Загружаем репозиторий и копируем на роутер

Откройте страницу проекта:

https://github.com/iliatraling/wol-tg-openwrt

Скачайте ZIP-архив ветки `main` и распакуйте его на компьютере. В PowerShell перейдите в каталог, где находится распакованная папка, и скопируйте её на роутер.

Пример:

```powershell
scp -O -r C:\NX32U-OpenWrt\wol-gateway-src\wol-tg-openwrt-main root@192.168.0.1:/tmp/
```

Замените локальный путь, имя распакованного каталога и IP роутера на свои.

Ключ `-O` принудительно использует старый SCP-протокол. Это необходимо для сборок OpenWrt без SFTP-сервера.

## 4. Устанавливаем приложение

В SSH-сессии на роутере перейдите в каталог, который скопировали, и запустите установщик:

```sh
cd /tmp/wol-tg-openwrt-main
sh install.sh
```

Установщик копирует приложение в системные каталоги:

```text
/usr/bin/wol-gateway
/usr/lib/wol-gateway/config.sh
/usr/lib/wol-gateway/telegram.sh
/usr/lib/wol-gateway/actions.sh
/etc/init.d/wol-gateway
/etc/wol-gateway.env.example
```

Существующий пример конфигурации не перезаписывается установщиком. Рабочий файл `/etc/wol-gateway.env` также не создаётся и не изменяется автоматически.

## 5. Создаём конфигурацию

Создайте рабочий файл на основе шаблона:

```sh
cp /etc/wol-gateway.env.example /etc/wol-gateway.env
chown root:root /etc/wol-gateway.env
chmod 600 /etc/wol-gateway.env
vi /etc/wol-gateway.env
```

Откройте файл и замени́те демонстрационные значения. Пример настройки одного устройства:

```ini
BOT_TOKEN="ВСТАВЬТЕ_ТОКЕН_ОТ_BOTFATHER"
ALLOWED_USER_IDS="1234567890"

TARGET_NAMES="home"
TARGET_LABELS="Домашний ПК"
TARGET_MACS="02:00:00:00:00:01"
TARGET_IPS="192.0.2.10"

DEFAULT_TARGETS="home"
NETWORK_INTERFACE="br-lan"
```

Здесь все значения, кроме структуры параметров, демонстрационные. Укажите:

- `BOT_TOKEN` — токен, выданный [@BotFather](https://t.me/BotFather). Не публикуйте его и не присылайте в переписке.
- `ALLOWED_USER_IDS` — числовой Telegram User ID пользователей, которым разрешено управлять ботом. Несколько ID разделяются запятой.
- `TARGET_NAMES` — уникальные алиасы устройств. Допустимы строчные латинские буквы, цифры и дефисы.
- `TARGET_LABELS` — названия, которые бот показывает в ответах.
- `TARGET_MACS` — MAC-адреса сетевых адаптеров, поддерживающих WOL.
- `TARGET_IPS` — IPv4-адреса для команды `/status`. Значение `0` отключает ping-проверку для устройства.
- `DEFAULT_TARGETS` — алиасы устройств, используемые командами `/wake` и `/status` без аргументов.
- `NETWORK_INTERFACE` — LAN-интерфейс, определённый на шаге 2.

Списки `TARGET_NAMES`, `TARGET_LABELS`, `TARGET_MACS` и `TARGET_IPS` должны содержать одинаковое количество элементов в одинаковом порядке. Например, первый алиас соответствует первому названию, первому MAC и первому IP.

Для добавления второго устройства добавьте второй элемент во все четыре списка. Несколько алиасов в `DEFAULT_TARGETS` разделяются запятыми.

**Не запускайте приложение с демонстрационными значениями.** IP `192.0.2.10` входит в документационный диапазон TEST-NET-1 и не предназначен для адресации реальных устройств. MAC `02:00:00:00:00:01` — демонстрационный локально администрируемый адрес.

Проверьте владельца и права файла:

```sh
ls -l /etc/wol-gateway.env
```

Файл должен принадлежать root и иметь права `-rw-------` (режим `600`). Приложение проверяет это при запуске.

## 6. Включаем автозапуск и запускаем службу

Выполните:

```sh
/etc/init.d/wol-gateway enable
/etc/init.d/wol-gateway start
```

Разница между командами:

- `enable` добавляет службу в автозапуск OpenWrt. После перезагрузки роутера она будет запущена автоматически.
- `start` запускает службу немедленно, не дожидаясь перезагрузки.

Для постоянной работы нужны обе команды.

## 7. Проверяем приложение

Проверьте состояние службы и сообщения системного журнала:

```sh
/etc/init.d/wol-gateway status
logread -e wol-gateway
tail -n 30 /tmp/wol-gateway.log
```

Откройте Telegram-бота и отправьте команды:

| Команда | Результат |
|---|---|
| `/help` | Справка по командам |
| `/wake` | WOL для устройств из `DEFAULT_TARGETS` |
| `/wake home` | WOL для устройства `home` |
| `/status` | Ping-проверка устройств из `DEFAULT_TARGETS` |

Сообщение об отправке Magic Packet не гарантирует включение устройства. Проверьте поддержку WOL, настройки BIOS/UEFI, драйвер сетевого адаптера и наличие питания на сетевом адаптере в выключенном состоянии.

Команда `/status` использует ICMP ping. Устройство может быть включено, но не отвечать на ping из-за настроек firewall или сетевого оборудования.

## 8. Проверяем автозапуск

Убедитесь, что ссылка автозапуска создана:

```sh
ls -l /etc/rc.d/S99wol-gateway
```

После тестовой перезагрузки проверьте службу:

```sh
/etc/init.d/wol-gateway status
logread -e wol-gateway
```

Файл конфигурации находится в постоянной файловой системе и сохраняется после перезагрузки. Журнал и файл ограничения частоты WOL расположены в `/tmp` (RAM) и после перезагрузки очищаются.

## Важные замечания

- Для одного токена Telegram должен работать только один long-polling-клиент. Перед запуском службы остановите другие приложения или экземпляры бота, которые вызывают `getUpdates` с этим токеном.
- Роутер устанавливает исходящее HTTPS-соединение с Telegram. Проброс входящих портов на WAN не нужен.
- При старте приложение сбрасывает старые ожидающие обновления Telegram. Команды, отправленные во время простоя, не должны выполняться после запуска.
- Повторная отправка WOL ограничена интервалом 15 секунд.
- Не удаляйте `/etc/wol-gateway.env` при обновлении приложения: в нём хранятся токен и настройки устройств.
- Если токен стал известен посторонним, отзовите его через BotFather и обновите конфигурацию на роутере.

## Обновление приложения

1. Скачайте свежий ZIP-архив ветки `main`.
2. Скопируйте каталог на роутер.
3. Запустите установщик из нового каталога:

```sh
cd /tmp/wol-tg-openwrt-main
sh install.sh
/etc/init.d/wol-gateway restart
```

Установщик обновляет исполняемые файлы и модули, но не перезаписывает существующий пример и рабочую конфигурацию. После обновления проверьте состояние службы и журнал.

## Удаление приложения

```sh
/etc/init.d/wol-gateway stop
/etc/init.d/wol-gateway disable
rm -f /usr/bin/wol-gateway /etc/init.d/wol-gateway
rm -rf /usr/lib/wol-gateway
```

Рабочая конфигурация `/etc/wol-gateway.env` и шаблон `/etc/wol-gateway.env.example` сохраняются намеренно. Удалите их вручную, если приложение больше не понадобится и сохранённый токен не требуется.


## Сохранение приложения при обновлении прошивки OpenWrt

При обновлении прошивки через `sysupgrade` произвольные файлы приложений могут не попасть в резервную копию. Чтобы WOL Gateway восстанавливался вместе с конфигурацией, добавьте его установленные файлы в `/etc/sysupgrade.conf`.

**1. Убедитесь, что файлы установлены:**

```sh
ls -ld \
/etc/init.d/wol-gateway \
/etc/wol-gateway.env \
/usr/bin/wol-gateway \
/usr/lib/wol-gateway
```

Если какой-либо путь отличается или отсутствует, не добавляйте его вслепую — сначала проверьте фактическое расположение файлов.

**2. Добавьте пути в список резервирования:**

```sh
cat >> /etc/sysupgrade.conf <<'EOF'
/etc/init.d/wol-gateway
/etc/wol-gateway.env
/usr/bin/wol-gateway
/usr/lib/wol-gateway
EOF
```

Каталог `/usr/lib/wol-gateway` содержит модули приложения. Команда `sysupgrade -l` покажет их отдельными строками.

**3. Проверьте, что все файлы попали в список:**

```sh
sysupgrade -l | grep wol-gateway
```

В проверенной установке Netis NX32U с OpenWrt 25.12.6 вывод содержал:

```text
/etc/init.d/wol-gateway
/etc/wol-gateway.env
/usr/bin/wol-gateway
/usr/lib/wol-gateway/actions.sh
/usr/lib/wol-gateway/config.sh
/usr/lib/wol-gateway/telegram.sh
```

**4. Перед обновлением прошивки создайте и скачайте резервную копию:**

На роутере:

```sh
sysupgrade -b /tmp/openwrt-backup.tar.gz
ls -lh /tmp/openwrt-backup.tar.gz
```

Скопируйте архив на компьютер. Например, из PowerShell:

```powershell
New-Item -ItemType Directory -Force "C:\\NX32U-OpenWrt\\backup"
scp -O root@192.168.0.1:/tmp/openwrt-backup.tar.gz "C:\\NX32U-OpenWrt\\backup\\openwrt-backup.tar.gz"
```

Замените IP роутера и путь на свои. Ключ `-O` нужен для сборок OpenWrt без SFTP-сервера.

**Важно:**

- `sysupgrade -l` показывает файлы, включённые в резервную копию; проверяйте его перед каждым обновлением.
- Резервная копия содержит `/etc/wol-gateway.env` с Telegram Bot Token. Храните архив приватно и не загружайте его в публичный репозиторий.
- Это резервирование конфигурации и файлов приложения, а не полный образ прошивки.
- Сохранение сторонних файлов зависит от механизма обновления и совместимости версий. После обновления проверьте службу командой `/etc/init.d/wol-gateway status` и журналом `logread -e wol-gateway`.
- Не используйте массовый `apk upgrade` для обновления системных пакетов OpenWrt. Для согласованного обновления прошивки следуйте процедуре, рекомендованной для вашей версии OpenWrt.

Для OpenWrt 25.12 и новее используется пакетный менеджер `apk`; в старых версиях может использоваться `opkg`. См. [шпаргалку перехода с opkg на apk](https://openwrt.org/docs/guide-user/additional-software/opkg-to-apk-cheatsheet).
