# WOL Telegram Gateway for OpenWrt

Лёгкий шлюз Wake-on-LAN для роутера OpenWrt. Управление домашними устройствами выполняется через Telegram-бота: роутер получает команды и отправляет Magic Packet непосредственно в локальную сеть.

> **Статус проекта:** архитектура и формат конфигурации зафиксированы. Реализация служб и обработчиков команд ещё не добавлена.

## Цели проекта

- **Лёгковесность.** Запуск непосредственно на OpenWrt без Docker, Python, Node.js или отдельного сервера.
- **Минимальные зависимости.** Штатный `ash`, `procd`, `curl` с TLS и утилита `etherwake`.
- **Безопасность.** Разрешённые Telegram User ID, ограниченный набор команд, проверка TLS, отсутствие входящих WAN-портов и секретов в Git.
- **Простая настройка.** Устройства и их параметры задаются списками в одном конфигурационном файле.
- **Независимость от домашнего ПК.** WOL отправляет сам роутер, поэтому выключенный компьютер не мешает отправке команды.

Проект рассчитан на OpenWrt и домашнюю LAN. Роутер должен иметь доступ в интернет для исходящих HTTPS-запросов к Telegram API.

## Архитектура

```text
Телефон
  |
  | Telegram
  v
Telegram Bot API
  ^
  | исходящий HTTPS / long polling
  v
OpenWrt — Netis NX32U
  |
  | etherwake / Magic Packet
  v
Домашняя локальная сеть
  |
  +-- Домашний ПК
  +-- Другие WOL-устройства
```

Telegram-бот работает на роутере как служба `procd`. Он получает обновления через long polling, проверяет отправителя и команду, затем вызывает только заранее определённое действие.

Домашний ПК может быть выключен: для отправки Magic Packet он не требуется. Удалённый доступ к приложениям на ПК (например, через Tailscale) — отдельная задача и будет доступен только после включения самого ПК.

## Команды Telegram

| Команда | Действие |
|---|---|
| `/wake` | Отправить Magic Packet всем устройствам из `DEFAULT_TARGETS` |
| `/wake home` | Включить устройство с алиасом `home` |
| `/wake home,work` | Включить несколько указанных устройств |
| `/status` | Проверить ping для устройств из `DEFAULT_TARGETS` |
| `/status home` | Проверить доступность устройства `home` по IP |
| `/help` | Показать список команд |

Алиас — короткий уникальный идентификатор устройства. В командах используется алиас, а пользователю показывается человекочитаемое имя из `TARGET_LABELS`.

### Поведение команд

- Если у устройства IP равен `0`, команда `/status` сообщает, что IP не указан, и не выполняет ping.
- Если IP задан, `/status` выполняет только ping. Дополнительная диагностика портов не предусмотрена.
- Успешная отправка Magic Packet означает, что пакет отправлен, но не гарантирует, что устройство включилось.
- `/wake` без аргумента использует список `DEFAULT_TARGETS`.

## Конфигурация

Шаблон конфигурации находится в `files/etc/wol-gateway.env.example`.

На роутере рабочий файл должен находиться по пути:

```sh
/etc/wol-gateway.env
```

Создайте его из шаблона и ограничьте доступ:

```sh
cp /etc/wol-gateway.env.example /etc/wol-gateway.env
chown root:root /etc/wol-gateway.env
chmod 600 /etc/wol-gateway.env
```

### Переменные

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота. Не публиковать и не отправлять в переписке. |
| `ALLOWED_USER_IDS` | Разрешённые Telegram User ID через запятую. |
| `TARGET_NAMES` | Алиасы устройств через запятую, например `home,work`. |
| `TARGET_LABELS` | Отображаемые названия в том же порядке, что и алиасы. |
| `TARGET_MACS` | MAC-адреса устройств в том же порядке. Обязательны для каждого устройства. |
| `TARGET_IPS` | IP-адреса для ping в том же порядке. Значение `0` означает, что IP не задан. |
| `DEFAULT_TARGETS` | Один или несколько алиасов, используемых командой `/wake` и `/status` без аргумента. |
| `NETWORK_INTERFACE` | LAN-интерфейс OpenWrt, через который отправляется Magic Packet, например `br-lan`. |

### Пример

```ini
BOT_TOKEN="ВСТАВЬТЕ_ТОКЕН_БОТА"
ALLOWED_USER_IDS="422503387,123456789"

TARGET_NAMES="home,work"
TARGET_LABELS="Домашний ПК,Рабочий ПК"
TARGET_MACS="18:C0:4D:6E:81:5D,AA:BB:CC:DD:EE:FF"
TARGET_IPS="192.168.0.134,0"

DEFAULT_TARGETS="home,work"
NETWORK_INTERFACE="br-lan"
```

В примере MAC второго устройства — демонстрационное значение. Замените его реальным MAC-адресом перед использованием.

### Правила заполнения списков

1. Во всех четырёх списках `TARGET_NAMES`, `TARGET_LABELS`, `TARGET_MACS` и `TARGET_IPS` должно быть одинаковое количество элементов.
2. Параметры устройства связываются по позиции: первый алиас соответствует первому имени, MAC и IP; второй — второму и так далее.
3. Алиасы должны быть уникальными и состоять из латинских букв, цифр и дефиса. Например: `home-pc,nas,work-pc`.
4. MAC обязателен. IP может быть задан как IPv4-адрес или `0`.
5. В `DEFAULT_TARGETS` указываются существующие алиасы. Несколько алиасов разделяются запятой.
6. Не используйте запятые внутри отображаемых названий: запятая является разделителем элементов.

При добавлении устройства нужно добавить по одному элементу в каждый из четырёх списков и при необходимости включить его алиас в `DEFAULT_TARGETS`.

## Меры безопасности

Архитектура предусматривает следующие меры:

- Проверка `from.id` по списку `ALLOWED_USER_IDS`. Отдельная проверка ID чата не используется.
- Обработка только известных команд и аргументов. Произвольное выполнение shell-команд через Telegram не допускается.
- Токен хранится в конфигурации на роутере с правами `root:root 600`; токен не включается в логи и Git.
- HTTPS-запросы к Telegram API выполняются с проверкой TLS-сертификата. Отключать проверку сертификата нельзя.
- Используется исходящий long polling. Входящие порты на WAN для работы бота не требуются.
- При запуске службы старые ожидающие обновления Telegram должны отбрасываться, чтобы команда, отправленная во время простоя, не выполнилась неожиданно после запуска.
- Повторная обработка обновлений ограничивается по `update_id`; для WOL предусматривается ограничение частоты запросов.
- Служебный лог хранится в RAM (`/tmp`), ограничивается по размеру и не содержит токенов.

**Важно:** одновременно должен работать только один polling-клиент с одним токеном бота. Перед переносом бота на OpenWrt остановите Android-клиент или другую службу, которая получает обновления этого же бота.

Эти меры описывают требования к реализации; сам факт наличия README и шаблона конфигурации не означает, что функциональность уже реализована или прошла аудит безопасности.

## Зависимости и системные требования

Планируемые компоненты:

- OpenWrt на роутере с доступом к LAN и интернету.
- `curl` с поддержкой TLS и корректным хранилищем сертификатов.
- `etherwake` для отправки Magic Packet.
- `procd` для управления службой (входит в OpenWrt).
- `ash` для shell-скриптов (входит в OpenWrt).

Не предполагается установка Docker, Python, Node.js, базы данных или отдельного сервера.

## Журналирование

Планируемый файл журнала:

```text
/tmp/wol-gateway.log
```

Журнал находится в RAM и очищается после перезагрузки роутера. В нём должны оставаться только последние записи; секреты и полный URL Telegram API с токеном записывать нельзя.
