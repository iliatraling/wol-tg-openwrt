# WOL Telegram Gateway for OpenWrt

Лёгкое приложение для удалённого включения компьютеров и других устройств по Wake-on-LAN через Telegram-бота. Приложение работает непосредственно на роутере OpenWrt и отправляет Magic Packet в локальную сеть.

<details>
<summary>Кратко о приложении</summary>

- Работает как штатная служба OpenWrt через `procd`.
- Не требует Docker, Python, Node.js, базы данных или отдельного сервера.
- Получает команды через исходящее HTTPS-соединение с Telegram Bot API (long polling).
- Разрешает управление только указанным Telegram User ID.
- Поддерживает несколько устройств и команды `/wake`, `/status`, `/help`.
- Поддерживает автозапуск после перезагрузки роутера.

</details>

## Статус

**Работоспособность проверена** на Netis NX32U с OpenWrt 25.12.6. Проверены установка, запуск службы, получение команд Telegram и отправка Wake-on-LAN.

Это небольшое специализированное приложение для OpenWrt. Перед переносом на другую модель роутера или другую сборку OpenWrt проверьте наличие зависимостей и фактическое имя LAN-интерфейса.

## Как это работает

```text
Телефон
   |
   | сообщение боту
   v
Telegram Bot API
   ^
   | исходящий HTTPS / long polling
   |
OpenWrt — служба wol-gateway
   |
   | проверка пользователя и команды
   | etherwake
   v
Локальная сеть (LAN)
   |
   +---- Компьютер
   +---- NAS
   +---- Другие WOL-устройства
```

Роутер сам обращается к Telegram и получает новые сообщения. После проверки Telegram User ID приложение выполняет только предусмотренные команды. Для работы не требуется открывать входящие порты на WAN.

Компьютер может быть выключен: Magic Packet отправляет роутер. Для фактического включения целевое устройство должно поддерживать Wake-on-LAN, а функция WOL должна быть разрешена в BIOS/UEFI и настройках сетевого адаптера. Для некоторых устройств также требуется питание в выключенном состоянии.

## Команды бота

| Команда | Действие |
|---|---|
| `/help` | Показать справку |
| `/wake` | Отправить Magic Packet устройствам из `DEFAULT_TARGETS` |
| `/wake home` | Отправить пакет устройству с алиасом `home` |
| `/wake home,work` | Отправить пакет нескольким устройствам |
| `/status` | Проверить устройства из `DEFAULT_TARGETS` |
| `/status home` | Проверить доступность устройства `home` |

**Важно:** сообщение об успешной отправке Magic Packet подтверждает только передачу пакета сетевому интерфейсу. Оно не подтверждает, что компьютер включился.

Команда `/status` выполняет один ping по заданному IPv4-адресу. Это проверка сетевой доступности, а не проверка питания или состояния операционной системы. Если устройство блокирует ICMP, результат может быть «недоступен», даже когда оно включено.

## Структура проекта

```text
files/
├── etc/
│   ├── init.d/
│   │   └── wol-gateway              # Служба procd
│   └── wol-gateway.env.example      # Шаблон конфигурации
└── usr/
    ├── bin/
    │   └── wol-gateway              # Главный процесс
    └── lib/
        └── wol-gateway/
            ├── config.sh            # Загрузка и проверка настроек
            ├── telegram.sh          # Вызовы Telegram Bot API
            └── actions.sh           # Команды, WOL и ping

install.sh                            # Установка файлов на роутер
Makefile                              # Установка в систему или staging-каталог
INSTALL.md                            # Пошаговая инструкция
README.md                             # Описание приложения
.github/workflows/shell-syntax.yml   # Проверка синтаксиса shell
```

### Назначение компонентов

- **`wol-gateway`** — загружает конфигурацию и модули, очищает ожидающие старые обновления Telegram, затем запускает цикл long polling.
- **`config.sh`** — проверяет права конфигурационного файла, обязательные параметры, Telegram ID, алиасы, MAC и IP.
- **`telegram.sh`** — выполняет HTTPS-запросы к Telegram Bot API.
- **`actions.sh`** — разбирает разрешённые команды, вызывает `etherwake` и проверяет доступность устройств через ping.
- **`/etc/init.d/wol-gateway`** — запускает приложение под управлением `procd` и задаёт политику перезапуска процесса.

## Установка

Полная инструкция с проверкой зависимостей, определением LAN-интерфейса и примером настройки находится в [INSTALL.md](INSTALL.md).

Краткая последовательность для OpenWrt 25.12:

```sh
apk update
apk add curl ca-bundle etherwake libubox

# После копирования репозитория на роутер:
cd /tmp/wol-tg-openwrt-main
sh install.sh

# Создать рабочую конфигурацию и защитить её:
cp /etc/wol-gateway.env.example /etc/wol-gateway.env
chown root:root /etc/wol-gateway.env
chmod 600 /etc/wol-gateway.env
vi /etc/wol-gateway.env

# Включить автозапуск и запустить сейчас:
/etc/init.d/wol-gateway enable
/etc/init.d/wol-gateway start
```

Перед запуском обязательно замените демонстрационные значения в конфигурации на реальные. Не публикуйте токен бота.

## Конфигурация

Рабочий файл на роутере: `/etc/wol-gateway.env`.

| Параметр | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота |
| `ALLOWED_USER_IDS` | Разрешённые Telegram User ID через запятую |
| `TARGET_NAMES` | Уникальные алиасы устройств |
| `TARGET_LABELS` | Отображаемые названия устройств |
| `TARGET_MACS` | MAC-адреса для Wake-on-LAN |
| `TARGET_IPS` | IPv4-адреса для ping; `0` отключает проверку |
| `DEFAULT_TARGETS` | Алиасы для команд без аргументов |
| `NETWORK_INTERFACE` | LAN-интерфейс отправки Magic Packet, обычно `br-lan` |

Списки `TARGET_NAMES`, `TARGET_LABELS`, `TARGET_MACS` и `TARGET_IPS` должны иметь одинаковое количество элементов и одинаковый порядок. Алиасы состоят из строчных латинских букв, цифр и дефисов.

В репозитории используются только демонстрационные значения. Пример IP-адреса относится к документационному диапазону, а MAC — к локально администрируемым адресам. Эти значения нужно заменить перед использованием.

## Безопасность и ограничения

- Доступ к командам проверяется по `message.from.id` и списку `ALLOWED_USER_IDS`.
- Обрабатываются только предусмотренные команды. Произвольное выполнение shell-команд из Telegram не реализовано.
- Конфигурация с токеном должна принадлежать `root` и иметь права `600` или строже.
- Токен передаётся `curl` через stdin-конфигурацию, а не через аргументы командной строки.
- TLS-проверка сертификата не отключается.
- Входящие WAN-порты не требуются.
- Одновременно должен работать только один long-polling-клиент с данным токеном. Остановите другие экземпляры бота перед запуском службы на OpenWrt.
- При запуске старые ожидающие обновления Telegram отбрасываются. Команды, отправленные во время простоя, не должны исполняться после старта.
- Повторный WOL ограничен интервалом 15 секунд.
- Файл журнала `/tmp/wol-gateway.log` находится в RAM и хранит последние 30 строк. После перезагрузки содержимое `/tmp` очищается.

Приложение не заменяет сетевую изоляцию и безопасность самого роутера. Пользователь с root-доступом к OpenWrt может прочитать конфигурацию и токен.

## Управление службой

```sh
# Запустить сейчас
/etc/init.d/wol-gateway start

# Остановить
/etc/init.d/wol-gateway stop

# Включить автозапуск после перезагрузки
/etc/init.d/wol-gateway enable

# Отключить автозапуск
/etc/init.d/wol-gateway disable

# Проверить состояние и журнал
/etc/init.d/wol-gateway status
logread -e wol-gateway
tail -n 30 /tmp/wol-gateway.log
```

`start` запускает службу сейчас. `enable` настраивает её автоматический запуск при загрузке OpenWrt. Для постоянной работы нужны обе команды.

## Удаление

Остановите службу, отключите автозапуск и удалите файлы приложения:

```sh
/etc/init.d/wol-gateway stop
/etc/init.d/wol-gateway disable
rm -f /usr/bin/wol-gateway /etc/init.d/wol-gateway
rm -rf /usr/lib/wol-gateway
```

Рабочая конфигурация `/etc/wol-gateway.env` намеренно не удаляется. Удалите её вручную только если больше не нужен сохранённый токен и настройки устройств.
